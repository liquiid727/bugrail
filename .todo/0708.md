在codeg的基础上，要强化增设一些功能和服务比如：
1. agent team 专家领域
专门配置
  1. idea-agent：用于构建构想讨论思考的agent（可以自由配置知识库+skill，尤其是brainstorm 以及 grillme这类）
方便用户自己厘清需求
  2. plan-agent 对于内置的/plan /spec这类的 可以添加我们的spec和plan规范和内容，基本上/plan 和 /spec的时候把我们这里内置的那一套的skill载入进去
  3. spec-agent
  4. execution-agent
  5. review-agent
  6. qa-agent
  7. test-agent
这里有几个好处
  这里配置专家agent（可以自由配置供应商和模型，这里可以降低成本以及不同的任务采用不同的类型的模型可以达到更好的效果）
  并且可以为其配置对应的知识+skill，不用每一个agent一次性拥有n个skill的内容

  我们这里是围绕prd-spec-issues-review-test-qa-ship 这里围绕文档来进行的；

甚至比较简单的问题比如：完成一个支付的xx，会走自动的架构-分派任务给执行的mentoragent，然后在分配给backend agent 和 frontend agent
这样的通过subagent和编排的方式快速的完成这些需求和问题的实现



  
2. codeg cli制作和开放
我们主要最常见是开一个spec-issues 拆分之后这里的内容会很多，我们又需要快速开发需要worktree+多个session并发的方式
然后最后合并起来的处理；
通过codeg-cli的能力的暴露；然后可以让cli直接操作开启worktree和session，让其能够可视化的来运行；方便人工查看情况和审核；


3. codebase/lsp / 代码索引

类似比如传统的IDE工具，我们都可以通过ctrl+click关键字 可以快速的跳转相关的这个变量的实现或者父类；类似jetbrains内置很多的索引就非常，因此他们才能够达到tab非常好用的情况
我们也要这里实现对应的代码索引，减少agent去检索目录的时间，也可以减少上下的输入和输出



4. issues：
在plan模式下，对应的窗口里面出现的plan让我们选择的计划，这里可以点击之后，将内容展开放在右侧的区域来进行查看
